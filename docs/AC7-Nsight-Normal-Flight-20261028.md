## 速度：从候选变为可解释的写入

资源：Texture2D212，`pID3D11Texture2D_uid_1688`，5120×1440 R16G16_UNORM，RTV53 / SRV264。

GPU读回结果：

- 185417个非零编码像素（中央2560×1440区域的约5.03%）。
- 所有非零像素的整数编码都为`(32767,32767)`；不是随机噪声或大片运动值。
- 非零包围框x1883–3236、y855–1178，与截图飞机所在区域一致，但包围框一致本身不证明所有材质/表面覆盖正确。
- `velocity-pass.raw`保留380后快照，`velocity.raw`为467后快照。

### 输出shader提供编码及jitter线索

PS278（UID4500）的反汇编：

```text
currentNDC = currentClip.xy / currentClip.w
previousNDC = previousClip.xy / previousClip.w
jitterAdjusted = (currentNDC - cb0[114].xy) - (previousNDC - cb0[114].zw)
selected = cb1[17].y > 0.5 ? currentNDC - previousNDC : jitterAdjusted
encoded = selected * 0.2495 + 0.499992
```

本帧检查的速度draw常量`cb1[17].y=0`；view常量`cb0[114]=(0,0,0,0)`，所以两分支在此帧相同。只证明**本帧这些常量为零**，不能证明所有画质/相机状态永远没有jitter。

解码消费shader使用`encodedUNORM * 4.008016 - 2.003978`，并以原始R>0判定有效。32767解码后约零位移，符合跟随相机下飞机基本停留原位的情境；不要把“185417个非零编码像素”表述为“185417个显著移动像素”。

### 原始零值要走相机回退

Draw427 / PS251明确读取深度及view常量CB1[110..113]：从当前屏幕坐标和硬件深度，计算前帧坐标，再做current-minus-previous。仅在RG16的R>0时用解码物体MV覆盖。因此背景速度不是零，不能直接将原始纹理送入NR/SR/FG。

本帧关键数据均已在捕获中：

- view buffer：`pID3D11Buffer_uid_58215`，最后映射更新blob123、4096bytes。
- 消费shader参数buffer：`pID3D11Buffer_uid_144`，Draw427时最后更新blob668。
- 参数[0]：`(5120,1440,1/5120,1/1440)`。
- 参数[16]：`(1280,-720,2559.5,719.5)`，明确关联中央有效区域和Y方向。
- view[110..113]为当前到前帧clip变换候选；view[114]为当前/前帧jitter候选，语义依据实际shader使用而非结构名称猜测。

[分析脚本](../tools/nsight/analyze-motion-20261028.cjs)据此生成`reference-motion-ndc.raw`（RG32_FLOAT、current-minus-previous NDC）和[motion-analysis.json](../artifacts/captures/nsight-flight-20261028/checkpoints/motion-analysis.json)。仅中央有效区域写入，外侧保持0；通过identity变换与编码零位移自检，所有重建值有限。

统计：

- 物体有效像素185417，位移近0（约0.00085像素的显示常数/量化残差）。
- 相机回退像素3500983；按本view半尺寸`(1280,-720)`换为像素，样本位移幅度P95约2.1845像素、P99约2.8840像素，分量范围X约±3.067、Y约-0.0022至1.7135。
- 深度为0的远处区域可能得到约0的相机位移，本帧这与纯平移下远处位移减小相符；不是拿0硬填相机速度。

这份参考场是对**观察到的游戏消费shader**的重现，不是已验证的DLSS motion契约。仍需验证时间方向/单位、当前/前帧采样位置、相邻帧对应、遮挡、透明云水/粒子及非飞机动态物体覆盖。近零飞机MV不能证明大幅物体运动下编码也正确。
