## 当前结论

用户完成 A/B：同上下文无 RenderDoc 的直接启动 A 正常；明确游戏工作目录、delayForDebugger=0 的 B 在闪屏后、主画面前失败。窗口化参数已传入，最新日志目标为 PID 139516。用户从崩溃后剪贴板提供的错误明确为：

```text
LowLevelFatalError ... D3D11RHI/Private/D3D11Util.cpp:182
Unreal Engine is exiting due to D3D device being lost.
Error: 0x887A0020 - INTERNAL_ERROR
```

微软 [DXGI 错误定义](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-error)将其命名为 `DXGI_ERROR_DRIVER_INTERNAL_ERROR`，说明驱动遇到问题且设备进入 removed 状态。这已将通用 Fatal error 收窄到 D3D11 设备丢失处理路径，但未确定触发它的 API、命令或责任组件，也不等于已证明 TDR、硬件故障或 NVIDIA 驱动缺陷。

用户确认 Steam 全局和游戏属性的内嵌页面开关测试前均关闭。DLL 加载不能证明功能启用，不再重复 Overlay 开关测试。下一项已完成版本对照：官方 1.45 的目标 PID 84600 同样报告 0x887A0020，配置保持一致，削弱仅 1.46 回归的解释。当前转为 [D3D11 验证层取证](AC7-D3D11-Validation.md)：普通用户输出收集链路已用独立小测试验证，游戏诊断配置已准备但尚未执行。

## 已确认事实与边界

1. 干净游戏经 Steam 启动的 PID 138000 已观察到至少 116 秒存活、窗口响应；用户也确认同上下文的直接启动 A 正常。
2. 游戏目录内 20 个额外文件已整体隔离，备份和恢复清单见 [干净基线](AC7-RenderDoc-Clean-Baseline.md)及 [状态清单](../../../docs/AC7-Clean-Test-State.json)。主 EXE 和官方 DLL 共 18 个文件与本机 Steam 缓存清单的大小/SHA-1 一致。PAK 只核对名称和大小，未做完整内容哈希；用户配置没有重置。
3. 无 mod 的 RenderDoc 目标 PID 130124、83672、114544 均完成握手、创建 D3D11 设备并进入 Presenting。不是完全没有注入、没有创建设备或不能识别 D3D11。
4. PID 130124：05:36:51 注入，05:36:56 Presenting，05:37:06 Not presenting，05:37:39 连接重置。PID 83672：05:38:28 注入，05:38:33 Presenting，05:38:35 连接重置。弹窗停留、焦点和用户动作未记录，不能据这些时长认定固定超时。
5. 早前实际配置曾为工作目录空、调试延迟 20；用户解释 EXE 选择后目录自动显示，且补填也无改善。最新 PID 114544 已确认明确工作目录、延迟 0。空字段可能自动推导，不能认定其本身错误，更不能继续将其作为首要原因。
6. 用户截图为启动闪屏（splash），Fatal error 在它出现后、主游戏画面出现前。日志 Presenting 不能直接等同于主游戏画面已出现，也不能精确绑定到截图窗口。
7. 保存的用户显示配置为 5120×1440、FullscreenMode=1、PreferredFullscreenMode=1、bUseHDRDisplayOutput=False。UE4 通常将模式 1 解释为无边框全屏；这是保存值，不是运行时交换链验证。独占全屏/HDR 不是当前优先推断。
8. 普通基线中观察到 gameoverlayrenderer64.dll，但 DLL 加载与内嵌页面功能启用不等价。两层开关关闭也不能证明所有内部 Steam Hook 均不存在；目前没有独立证据继续优先怀疑它。
9. ProcDump 提前附加产生不同的 T:0000065432，没有到 D3D11 设备创建。所得 dump 注释是 Process termination，没有异常流，不能借此定位原来的渲染阶段失败。
10. 未找到与这些失败 PID 对应的新 WER 异常记录/异常转储。但用户提供的 UE 错误已明确设备丢失原因为 0x887A0020；不再将“仅有通用 Fatal error，无法判断类别”作为当前状态。
11. 最新配置为 `-windowed`、明确游戏工作目录、delayForDebugger=0。PID 139516 于 06:02:13 到 Presenting，06:02:16 连接重置；用户栈没有 PID，其与该运行的关联依据时间和当前设置，不能说栈自身携带了 PID。
12. 错误中的 `E:\P4S3\...\D3D11Util.cpp` 是构建时嵌入的源码路径，不表示本机缺少该文件。182 行属于设备丢失的报告位置，未定位最初触发的图形调用。UnknownFunction 地址缺少匹配符号、模块装载信息，不能直接定位游戏内部函数；KERNELBASE 栈顶也不是系统 DLL 有问题的证明。
13. 有限的近 20 分钟事件查询未找到能对应本次运行的驱动重置/异常事件；曾有较早的 Auto HDR 通知，但未关联到本次 AC7 PID。游戏配置的 HDR 关闭不等同于 Windows Auto HDR 一定关闭，现阶段不据此归因。

日志/配置快照：`../artifacts/diagnostics/renderdoc-clean-failure/`、`../artifacts/diagnostics/renderdoc-controlled-B/`。

## 假设矩阵

以下是诊断顺序和证据强弱，不是原因概率。

| 假设 | 当前支持与限制 | 验证方向 |
| --- | --- | --- |
| H1：直接启动上下文或启动配置 | A 正常，补填工作目录和零延迟的 B 仍失败，优先级降低。 | 不重复相同 A/B 或继续归咎工作目录。不同 Steam 错误另行记录。 |
| H2：RenderDoc 的 D3D11 包装与游戏/中间件/当前驱动不兼容 | 无 mod 的 A 正常、B 失败，现已确认 B 的设备丢失原因码为 DXGI_ERROR_DRIVER_INTERNAL_ERROR；具体失败调用和责任组件仍未知。 | 固定驱动、游戏和启动参数，只比较另一套适用的官方 RenderDoc。 |
| H3：Steam Overlay 冲突 | 用户确认两层功能开关一直关闭，降低活动 Overlay 功能导致冲突的优先级。仅有 DLL 加载不足以继续支持此推断。 | 不重复开关，不删除或拦截 Steam DLL。只有新的调用栈、事件或独立对照指向它时再提高优先级。 |
| H4：游戏/Steam 主动结束 | 已有 UE4 因设备丢失进入 Fatal 处理路径的证据，泛指 Steam/保护检查主动结束的解释优先级降低；调试器引发的 Steam 错误仍是独立症状。 | 不继续按 DRM 原因推断，只有新的调用栈或独立证据指向该方向才提高优先级。 |
| H5：窗口或交换链呈现路径与包装冲突 | Fatal error 在闪屏后、主画面前；这是时间阶段，不能直接证明全屏切换失败。保存值为无边框全屏、HDR 关闭。 | 当前只加 `-windowed`。若能越过闪屏，支持窗口/呈现路径参与；失败时需先确认参数是否生效。 |
| H6：特定 RenderDoc 版本或 GPU/驱动组合问题 | 当前只有 1.46 与一个驱动组合，没有明确 DEVICE_REMOVED/HUNG。 | 窗口化对照之后，选择经发布说明核实适用的另一套官方便携版，其他条件固定。某版成功只支持版本相关，不能直接判驱动损坏。 |
| H7：已有 mod 或游戏二进制损坏 | 完整隔离后仍失败，18 个二进制与缓存清单匹配，优先级降低；不覆盖所有外部注入、用户配置与 PAK 内容。 | 暂不重复移除 mod，不先重装游戏/Steam。出现新的文件异常或普通启动也失败时再提高优先级。 |

## 日志线索不等于结论

- `NvAPI disabled: Returning NULL` 是 RenderDoc 改变了部分 NvAPI 查询的可用性，值得关注，但不是驱动自身报错或崩溃点的证明。
- `IDXGIAdapterInternal2` 的 unsupported-interface 警告不自动表示应用不能继续，后续已到 Presenting。
- 多次创建设备和短暂出现 WARP 可能是能力探测。没有对应失败返回值/最终设备描述前，不认定 GPU 回退或耗尽。
- WSAECONNRESET 只证明连接中断，不能单独区分异常崩溃、主动退出、外部终止或用户关闭错误对话框。
- 没有有效 .rdc，用户也未按捕获键，不优先按“捕获文件太大/保存捕获耗尽内存”排查。

## 官方 RenderDoc 版本对照记录

目标：判断当前设备丢失是否依赖 RenderDoc 1.46 的具体实现。已从官方构建页下载紧邻的 1.45 x64 完整便携包，核对核心文件签名和版本，并打开窗口 `RenderDoc v1.45`（PID 134392）。其自身 D3D11 探测识别 RTX 5080 / 32.0.16.1742，但尚未在 AC7 中验证。发布说明没有对本问题给出专项修复保证。详细来源、哈希和进程记录见 [版本对照记录](RenderDoc-Version-Comparison.json)。

固定内容：同一驱动、同一无 mod 游戏、同一 App ID、工作目录和权限、当前命令行 `-windowed`、零调试延迟及捕获选项。不在这一轮同时改 HDR、分辨率、NvAPI、驱动或系统转储配置。实际 1.46 配置与 `同一窗口化预设`（清理时已移除的实验文件）已做 JSON 语义一致性检查；下一步由用户在新开的 1.45 窗口加载此设置并 Launch 一次。1.46 保留，游戏目录未放入新的 DLL。CLI 出现并行版本的 Vulkan 层注册提示，未修复注册；本次 D3D11 对照不改变它。

预期：

- 另一版能稳定进入菜单：支持版本相关兼容性；保留该版本完成最小捕获，再确认复现。仍不能仅凭结果判定谁的代码有错。
- 另一版同样报告 0x887A0020：特定 1.46 回归的解释被削弱，后续再研究游戏图形中间件/驱动交互。两个版本失败不能证明所有版本均不兼容。
- 另一版出现不同错误或不能启动：单独记录，不作为同一设备丢失的正反证据。

## 窗口化参数对照记录（已传入，仍失败）

用户此次运行后的最新设置确认带 `-windowed`，且仍发生设备丢失。由于主窗口未成功出现，不能确认游戏实际采用的窗口模式，因此这项结果不能完全排除窗口/呈现路径。以下保留本项原预期作为解释边界。

测试目标：区分“当前无边框全屏窗口/呈现路径参与失败”与“普通窗口路径也同样失败”。这是诊断假设，不是从闪屏顺序直接确定交换链故障。

`窗口化候选配置`（清理时已移除的实验文件）以当前实际 B 配置为基准，只将 commandLine 从空改为 `-windowed`。工作目录、delayForDebugger=0、捕获选项、工具版本、App ID 均不变。不附加 ResX/ResY、不改 HDR、不启用 ProcDump 或注册表监视。仅在项目内准备，未执行。

预期与停止条件：

- 参数生效且 B 以普通窗口越过闪屏、进入菜单：支持窗口/呈现路径参与，不等于已找到具体失败函数。先确认稳定，再考虑最小抓帧，不马上恢复全部 mod。
- 参数已确认生效，但仍在同一阶段 Fatal error：降低显示模式假设的优先级，下一项才单独比较另一套官方 RenderDoc。
- 主窗口出现前就退出，不能确认参数是否被采用：结果不充分，不能排除显示模式。此时用已成功的无工具 A 加同一参数确认普通窗口路径是否受支持，不能将未验证的参数当成有效对照。
- 错误类型或阶段改变：单列结果，不直接判定改善或根因。

一个启动参数是一个受控输入，但可能间接改变窗口尺寸、实际渲染区域或保存的显示模式，需记录实际结果，不能声称其他所有运行时条件必然相同。若游戏保存了新的显示配置，恢复前核对本轮实际改动，勿覆盖用户后续设置。
