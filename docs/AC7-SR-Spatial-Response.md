# SR Reset高光差异：空间定位和单帧控制

本轮解决的是上一阶段“输入峰值166、输出102.8125且局部差异大”的归因范围。**已有数据证明差异高度集中在稀疏海面高光；新增一次合成Reset控制证明该诊断配置存在明显的空间结构相关响应，不支持固定HDR上限约103或单纯统一曝光倍率的解释。** 仍不能证明游戏真实pre-exposure、私有模型算法或画质正确性。

## 原始两组raw的空间统计

[analyze_sr_reset.cjs](../tools/nr/analyze_sr_reset.cjs)只分析上一阶段保存的FP16 raw，不启动NGX。原始SHA256与输入合同/输出检查相符，复算像素变化数、峰值、平均/最大绝对差异与原报告一致。包含half解码、恒等、统一倍率以及降峰值但数值和守恒的平滑自检。

| 指标 | 原始HDR→SR | NR后HDR→SR |
| --- | --- | --- |
| 输入峰值位置，工作rect像素 | (525,983)，R=166 | 同左 |
| 输出峰值位置 | (459,1167)，R=102.8125 | 同左 |
| 所有RGB数值和，输出/输入 | 0.874586 | 0.872466 |
| 输入峰值<1区域RGB和比例 | 约1.001 | 约1.001 |
| 输入峰值≥10像素数 | 17,474，约0.474%全图 | 同左 |
| 上述像素贡献的绝对差异 | 89.83% | 90.04% |
| 输出RGB全部处于输入对应3×3范围的像素比例 | 99.54% | 99.63% |

3×3检查容差`max(1e-5,邻域绝对最大值*0.002)`，只是空间关系统计，不是过滤算法鉴定或正确性条件。RGB数值和不是经过光度标定的能量。

最大差异都在工作rect **(536,1065)**，完整捕获x=1816：原始输入RGB=(160,125,94)，输出约(10.71094,8.36719,6.29297)。对照原场景和[局部图](../artifacts/research/official-sr/spatial-analysis-v1/local-comparison-v2.png)可见这是海面小高光；飞机边缘也出现平滑变化。该点17×17邻域的RGB数值和仅保留44.53%（NR后44.15%），所以不能简单宣称“峰值只是搬到相邻像素、亮度守恒”。

证据：[原始HDR完整统计](../artifacts/research/official-sr/spatial-analysis-v1/baseline.json)、[NR后完整统计](../artifacts/research/official-sr/spatial-analysis-v1/after-nr.json)。

## 公共参数复核与保留意见

单个只读Luna scout比较正式D3D12 helper、指南和当前代码。主会话复核helper结构/映射：本诊断创建尺寸/flags、核心颜色/深度/速度/输出、Reset、jitter、render尺寸、曝光/preExposure都有显式设置。TonemapperType和FrameTimeDelta在该helper结构中属于“OPTIONAL - only for research purposes”段，不能仅因helper设置就判它们是必需缺项。本轮没有为了这些字段填虚构帧时间或改tonemapper。

完整helper也显式设置各输入/输出subrect base，本工具没有显式设置base。对于本次新参数对象、全幅独立纹理和关闭output subrect的同尺寸样本，没有现有文本证明这是求值必需缺项；**未设置时实际NGX行为仍未单独证明**，不外推到带偏移的实时资源。没有在这一轮额外修改SR调用参数，控制沿用上一轮行为。

child报告把MV单位列为未知，是其有限文件核对的边界：主会话已有[单帧输入合同](../artifacts/research/official-sr/reset-diagnostic-baseline-input/diagnostic-contract.json)和真实捕获规范化证据，输入按向后像素位移准备、NGX scale1；但**真实相邻帧时域标定仍未知**。这两者不能混写成“没有任何MV转换证据”或“时域已标定”。不需要据child保留意见重复已有转换。

[保留的参数核对摘要](../artifacts/research/official-sr/sr-reset-public-parameter-audit.md)，run `580e8aca-e743-4a50-89e1-436480fd79a3`；摘要只作证据，主会话保留实验/验收决定。原始托管outputReference及本地保留映射在阶段检查中。

## 当前判断与下一步

1. “SR不能输出原始幅度HDR/固定钳到103”的猜测在本控制下不成立；大差异具有空间结构相关性。
2. 海面稀疏高光实际衰减是事实，17×17窗口内也未守恒；**画质仍不验收**，不靠NR高光保护或人工补回掩盖SR行为。
3. 单Reset无历史，不能代表稳定运行时的细节保持。下一有价值门槛是**可信相邻帧序列及实际曝光/view语义**；重复当前同一帧作多次Evaluate不能替代。
4. 当前没有证据表明修改可选参数或连续猜preExposure能解决语义问题，停止该类试跑。本轮不回写SR、不部署游戏、不改SDK/模型，不提前定宿主或桥。

已有单帧捕获可继续用于具体view/曝光字段语义定位，但有限shader中未找到不是不存在的证明。若需要用户采样，必须先给出明确帧边界和导出方案，避开已知Nsight巨量多帧捕获问题；**现在不要求用户盲目重复F11或重抓普通截图**。真实游戏pre-exposure依然未知，不以本次合成控制代替校准。
